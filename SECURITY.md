# Security policy

## Supported versions
| Version | Supported |
| ------- | --------- |
| 0.1.x   | yes       |

## Reporting a vulnerability
The starter code ends up on real business websites, so we take reports seriously: for example an
escaping or nonce gap in the core plugin, a way around the enquiry pipeline, or a script that could
leak a secret or deploy the wrong code.

1. **Do not open a public issue.**
2. Use GitHub's private reporting: the repository's **Security** tab, then **Report a vulnerability**.
3. Include what is affected, how to reproduce it, and the impact you expect.

We aim to answer within 7 days and to agree a fix and disclosure date with you.
If you built a site from an older version, the fix notes in `CHANGELOG.md` say what to copy into it.
